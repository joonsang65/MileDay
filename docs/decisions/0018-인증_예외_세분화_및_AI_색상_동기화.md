## 1. 배경 (Context & Problem Statement)

MileDay의 사용자 인증 및 AI 일정 생성 파이프라인에서 프론트엔드-백엔드 간의 계약 정밀도를 저해하는 두 가지 문제가 발생했다.

### 문제 1: 이메일 미인증 로그인 시 자격증명 오류와 구별 불가
- **증상**: Supabase Auth에서 회원가입 후 이메일 인증(Email Confirmation)이 완료되지 않은 상태에서 로그인을 시도할 때, 백엔드가 이를 일반적인 아이디/비밀번호 불일치와 동일한 `AUTH_INVALID_CREDENTIALS` (HTTP 401)로 응답함.
- **사용자 혼란**: 사용자는 비밀번호를 올바르게 입력했음에도 "이메일 또는 비밀번호가 올바르지 않습니다"라는 오안내를 받게 되어, 비밀번호 재설정을 시도하거나 가입이 실패했다고 오인하게 됨.

### 문제 2: AI 일정 생성 초안의 목표-마일스톤 색상 불일치
- **증상**: Gemini API 기반 AI 일정 생성 초안(`POST /ai/schedule/suggest` 또는 `POST /ai/schedule/draft`)에서 부모 목표(Goal)는 기본 녹색 계열(`#7F9278`)로 생성되었으나, 하위 마일스톤들(Milestones)은 별도의 하드코딩된 상수(`DEFAULT_MILESTONE_COLOR = #55A873`)가 적용되어 생성됨.
- **시각적 결함**: 캘린더와 Day View에서 한 목표에 속한 작업들이 서로 다른 색상 테마로 어색하게 렌더링되어 목표-마일스톤 간의 시각적 소속감이 약화됨.

## 2. 원인 분석 (Deep Dive Root Cause Analysis)

### 2.1 Supabase Auth 에러 파싱 누락 (`auth_service.py`)
Supabase Auth 라이브러리는 이메일 미인증 시 예외 메시지에 `email_not_confirmed`, `email not verified` 등의 문자열을 포함하여 반환한다. 그러나 백엔드의 에러 매핑 함수 `_map_login_error`는 재시도 가능한 네트워크 오류(`_is_retryable_auth_error`) 외에는 모두 `AuthInvalidCredentialsError`로 일괄 매핑하고 있었다.

```python
# [기존 auth_service.py의 오류 매핑]
def _map_login_error(exc: Exception) -> Exception:
    if _is_retryable_auth_error(exc):
        return SupabaseUnavailableError(...)
    # 이메일 미인증도 자격증명 오류로 일괄 변환됨!
    return AuthInvalidCredentialsError(detail=_safe_detail(exc))
```

### 2.2 하드코딩된 마일스톤 색상 상수 (`ai_schedule_service.py`)
`build_create_goal_payload`에서 목표의 `color` 속성과 마일스톤의 `color` 속성을 각각 독립된 기본 상수로 지정하고 있었다.

```python
# [기존 ai_schedule_service.py]
DEFAULT_GOAL_COLOR = "#7F9278"
DEFAULT_MILESTONE_COLOR = "#55A873"  # 목표와 다른 색상

def build_create_goal_payload(draft: dict[str, Any]) -> dict[str, Any]:
    return {
        "goal": { ..., "color": DEFAULT_GOAL_COLOR },
        "milestones": [
            { ..., "color": DEFAULT_MILESTONE_COLOR }  # 부모 색상과 불일치!
        ]
    }
```

## 3. 해결 방향 및 아키텍처 결정 (Architecture Decisions)

```mermaid
flowchart TD
    A[Supabase Auth 로그인 예외 발생] --> B{_is_retryable_auth_error?}
    B -- Yes --> C[SupabaseUnavailableError 반환 (502)]
    B -- No --> D{_is_email_not_confirmed_error?}
    D -- Yes --> E[AuthEmailNotConfirmedError 반환 (401, AUTH_EMAIL_NOT_CONFIRMED)]
    D -- No --> F[AuthInvalidCredentialsError 반환 (401, AUTH_INVALID_CREDENTIALS)]
    
    G[AI 일정 생성 요청] --> H[Gemini LLM 일정 추론]
    H --> I[build_create_goal_payload]
    I --> J[goal_color = DEFAULT_GOAL_COLOR 정의]
    J --> K[Goal 및 하위 Milestone 모두 goal_color 상속 적용]
```

### 결정 1: `AUTH_EMAIL_NOT_CONFIRMED` 전용 에러 코드 도입
1. `backend/app/schemas/common.py`의 `ErrorCode` 열거형에 `AUTH_EMAIL_NOT_CONFIRMED`를 추가한다.
2. `backend/app/exceptions/auth.py`에 `AuthEmailNotConfirmedError` 커스텀 예외 클래스를 정의한다.
3. `auth_service.py`에 `_is_email_not_confirmed_error()` 검출 로직을 추가하고, `_safe_detail()`에서 예외의 `status`, `code`, `message`를 안전하게 보존하도록 개선한다.
4. 프론트엔드 에러 메시지 맵(`errorMessages.ts`)에 한국어/영어 안내 문구를 매핑한다.

### 결정 2: AI 생성 마일스톤 색상의 부모 목표 색상 상속
1. `DEFAULT_MILESTONE_COLOR` 상수를 완전히 제거한다.
2. 마일스톤 생성 페이로드를 조립할 때 목표의 `goal_color`를 하위 모든 마일스톤에 일괄 할당하여 디자인 일관성을 확보한다.

## 4. 상세 구현 내용 (Implementation Details)

### 4.1 `backend/app/exceptions/auth.py`
```python
class AuthEmailNotConfirmedError(MileDayBaseException):
    def __init__(self, detail: object | None = None):
        super().__init__(
            status_code=status.HTTP_401_UNAUTHORIZED,
            error_code=ErrorCode.AUTH_EMAIL_NOT_CONFIRMED,
            message="Please confirm your email before logging in.",
            detail=detail,
        )
```

### 4.2 `backend/app/services/auth_service.py`
```python
def _is_email_not_confirmed_error(exc: Exception) -> bool:
    text = _auth_error_text(exc)
    return (
        "email_not_confirmed" in text
        or "email not confirmed" in text
        or "email not verified" in text
    )

def _safe_detail(exc: Exception) -> dict[str, str]:
    detail = {"type": exc.__class__.__name__}
    for key in ("status", "code", "message"):
        value = getattr(exc, key, None)
        if value is not None:
            detail[key] = str(value)
    if "message" not in detail and str(exc):
        detail["message"] = str(exc)
    return detail

def _map_login_error(exc: Exception) -> Exception:
    if _is_retryable_auth_error(exc):
        return SupabaseUnavailableError(
            message="Supabase Auth login request failed.",
            detail=_safe_detail(exc),
        )
    if _is_email_not_confirmed_error(exc):
        return AuthEmailNotConfirmedError(detail=_safe_detail(exc))
    return AuthInvalidCredentialsError(detail=_safe_detail(exc))
```

### 4.3 `backend/app/services/ai_schedule_service.py`
```python
DEFAULT_GOAL_COLOR = "#7F9278"

def build_create_goal_payload(draft: dict[str, Any]) -> dict[str, Any]:
    goal = draft["goal"]
    milestones = draft["milestones"]
    goal_color = DEFAULT_GOAL_COLOR
    return {
        "goal": {
            "title": goal["title"],
            "deadline": goal["deadline"],
            "is_recurring": False,
            "recurrence_type": None,
            "color": goal_color,
        },
        "milestones": [
            {
                "title": item["title"],
                "scheduled_date": item["scheduled_date"],
                "color": goal_color,  # 목표 색상과 100% 동일하게 통일
                "is_completed": False,
            }
            for item in milestones
        ],
    }
```

## 6. 검증 및 결과 (Validation & Impact)

1. **인증 테스트**:
   - `tests/test_auth_service.py`: `Email not confirmed` 에러 발생 시 `AuthEmailNotConfirmedError`가 정확한 HTTP 401과 `AUTH_EMAIL_NOT_CONFIRMED` 코드로 반환되는지 단위 테스트 검증 (통과).
2. **AI 서비스 테스트**:
   - `tests/test_ai_schedule_service.py` & `tests/test_ai_schedule_routes.py`: AI 일정 초안 생성 시 모든 마일스톤이 부모 목표와 동일한 `#7F9278` 색상 값을 갖는지 검증 (통과).
3. **문서 동기화**:
   - `docs/error_logging.md` 및 `docs/codex_rules.md`에 `AUTH_EMAIL_NOT_CONFIRMED` 에러 코드 명시 반영 완료.
